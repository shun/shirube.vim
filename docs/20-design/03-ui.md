# UI/UX

## 目的
- 変更内容を明確に提示し、ユーザーが安全に実行可否を判断できるようにする。

## UI モード
- `ui_mode="float"`: フローティング UI を使用する。
  - Neovim: Floating Window
  - Vim: Popup
- `ui_mode="buffer"`: 確認用の専用バッファを表示する。
- Vim で Popup が利用できない場合は confirm() にフォールバックする。

## 確認 UI の表示内容
- Action の種類と対象パスを一覧で表示する。
- 色分けは以下を基準とする。
  - Create: 緑
  - Delete: 赤
  - Move: 黄
- 一覧は読み取り専用として扱い、ユーザーは編集できない。

## 表示
- ディレクトリ名は末尾に `/` を付けて表示する。
- ディレクトリとファイルは文字色を分ける。
- メタ情報（`[d]/[f]`、サイズ、パーミッション）は右寄せで整列表示する。

## 入力
- `y` または `<CR>` で実行、`n` でキャンセル。
- それ以外の入力はキャンセル扱いとする。

## ナビゲーション
- `keymaps` で指定されたキーに応じて動作する（デフォルト無効）。
  - `open_cursor`: カーソル行を開く（ディレクトリ行は移動、ファイル行は開く）。
  - `open_parent`: 親ディレクトリへ移動する。
  - `close`: Shirube バッファを閉じる。

## グローバルキーマップ
- `keymaps_global` で指定されたキーに応じて Shirube を開く（デフォルト無効）。
  - `open_shirube`: 現在のバッファ/ディレクトリから Shirube を開く。

## 専用バッファの仕様
- `buftype=nofile`、`bufhidden=wipe`、`swapfile=0` を基本とする。
- 表示後に入力を受け取り、確定後はバッファを閉じる。

## Vim/Neovim 差異吸収
- denops-std を介して Popup/Floating の API 差を吸収する。
- 取得できない API は confirm() へフォールバックする。
